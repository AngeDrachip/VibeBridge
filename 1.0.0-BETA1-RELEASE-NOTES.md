# Vibe 1.0.0-beta.1 — `.hmod` content release

First beta of Vibe: a compatibility layer for running Minecraft Forge mods with
Horizon. The headline artifact is `litematicatool.hmod`, a Horizon content mod
Vibe built from a real third-party Forge jar, with a working item.

## The `.hmod` artifacts

- `litematicatool.hmod` — built from `litematicatool-forge-2.0.0.jar` (MIT).
  It carries the mod's assets, its recipe, and an item declaration:
  `the_stick` copies the vanilla `minecraft:stick` template, with the mod's own
  model and texture. Verified in Horizon 0.2.97 on Minecraft 26.3:
  `horizon-ctl give litematicatool:the_stick` answers `{"given":1,"ok":true}`
  and the item appears in the inventory.
- `vibetest.hmod` — a minimal test bundle with one block and two items
  (`vibetest:ruby`, `vibetest:ruby_block`), used to prove the content path.
- `SHA256SUMS.txt` — checksums for every asset.

Install a bundle and turn it on in one step:

```powershell
vibe horizon install litematicatool.hmod
# Installed ...\horizon-mods\litematicatool.hmod
#   horizon-mods.txt: mod.litematicatool:true (on)
```

Then start Horizon and run `/give litematicatool:the_stick`.

## Highlights

- `vibe horizon export --item-template NAME=TEMPLATE` declares an item a Forge
  mod registered in Java: it writes `data/<id>/horizon/item/NAME.json` copying
  a vanilla template, and the 26.3 `assets/<id>/items/NAME.json` definition
  when the jar ships the old `assets/<id>/models/item/NAME.json`.
- `vibe horizon connect` verifies a live Horizon instance end to end:
  `horizon-ctl` discovery, control socket, player in world, pending chunks,
  Minecraft version, and the Horizon content API version.
- `horizon-ctl` is discovered inside Horizon launcher installations
  (`versions/<tag>/horizon-ctl.exe`), so `VIBE_HORIZON_CTL` is optional.
- `vibe horizon export`, `vibe horizon validate`, and `vibe horizon install`
  turn a Forge jar's assets and data into a validated `.hmod` content bundle.
- `vibe horizon install` writes `mod.<id>:true` to `horizon-mods.txt` (Horizon
  leaves a content mod off until that line exists) and defaults `--game-dir` to
  the Horizon game home (`HORIZON_HOME`, then `%APPDATA%\horizon`), the folder
  holding `options.txt`.
- 23 `vibe-horizon` unit tests cover discovery, connection checks, export,
  validation, installation, enabling, and item declarations.

## What Vibe does and does not do

Vibe does **not** make Horizon run Java mods. Horizon is a Rust engine with no
JVM. Vibe runs a small, clean-room subset of the Forge API in a separate Java
process, reports when a mod needs anything outside that subset, and can carry a
jar's assets and data into Horizon through Horizon's documented content-mod
format.

The item declared in `litematicatool.hmod` copies the vanilla stick's
behaviour. The mod's Java `TheStickItem` class is not executed, so its custom
logic is not present.

## Verified against Horizon 0.2.97

- `vibe horizon connect` reports `ready: yes` against a running Minecraft 26.3
  game in the `VibeTest` world.
- Horizon loads the Vibe-exported bundles:
  `Horizon: content from 2 mod(s) in ...\.horizon-cache\mod-content`.
- Registered content: 1 block and 3 items; the game went from 35,723 to 35,724
  block states and from 1,658 to 1,661 items.
- `horizon-ctl give litematicatool:the_stick` → `{"given":1,"ok":true}`, and
  the item is in the inventory.
- `horizon-ctl give vibetest:ruby` and `give vibetest:ruby_block` →
  `{"given":1,"ok":true}`.

## Known limitations

- Horizon content mods carry assets and data only. Java entrypoints, Mixins,
  access transformers, and coremods are reported, never executed.
- An item or block a mod registers only in Java has no declaration unless you
  state one with `--item-template`; there is no automatic detection.
- Horizon targets Minecraft 26.3. A jar written for an older pack format is
  copied byte for byte and may not be readable by Horizon.

## Requirements

- Java 17 or newer for the Java sidecar (`vibe run`).
- Optional: a Horizon installation with `horizon-ctl` for `vibe horizon probe`
  and `vibe horizon connect`.

## Verify

```powershell
vibe doctor
vibe horizon probe
vibe horizon connect
vibe horizon validate litematicatool.hmod
```
