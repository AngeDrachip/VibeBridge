# Vibe 1.0.0-beta.1

Vibe is the compatibility layer you install once. Then you drop Java Forge mods
into `mods/` and run them directly: Vibe reads the original jars, decides what
it can execute, and runs the supported Forge lifecycle in its bundled JVM
sidecar. For Horizon, Vibe also exports a jar's assets and data as a `.hmod`
content mod.

## Install

1. Download `vibe-1.0.0-beta.1-windows-x86_64.zip` and unpack it anywhere.
2. Run `vibe doctor` (checks Java, the bundled runtime, and Horizon).
3. Drop Forge jars into `mods/`.
4. Run `vibe run mods`.

```powershell
.\vibe.exe doctor
.\vibe.exe setup
Copy-Item .\SomeForgeMod.jar .\mods\
.\vibe.exe run mods
```

The zip is self-contained: `vibe.exe` finds `java/build/vibe-runtime.jar` and the
optimized JRE at `java/runtime/` beside it, so neither a source checkout nor a
Java install is needed. The JRE is a ~50 MB jlink image with a CDS archive;
startup is ~78 ms with CDS instead of ~131 ms without.

## Horizon native mod (`.hnmod`)

The release also ships `vibe-1.0.0-beta.1.hnmod`, Vibe packaged for Horizon's
native mod system. The launcher compiles it into the game, so opening a world
starts Vibe's JVM sidecar automatically and `/vibe` commands answer in chat:

```text
/vibe status   /vibe mods   /vibe start   /vibe stop
/vibe reload   /vibe export /vibe help
```

Install it on the Mods page (**Add from GitHub** →
`https://github.com/AngeDrachip/VibeBridge`, or the instance's
`horizon-native-mods/` folder), press **Build**, then unpack this release zip
inside the instance folder so `vibe\vibe.exe`,
`vibe\java\build\vibe-runtime.jar` and `vibe\java\runtime\` exist. Forge jars go
in `<instance>\vibe\mods\`. A `.hnmod` carries source only, so the JRE ships in
that Vibe folder; the mod hands it to the sidecar as `VIBE_JAVA`.

Verified on Horizon `2ebf00a0281c592f79191e76fce0e7d522c6f425` (nightly
2026-11-07, hooks 44) with horizon-mixins `d9c83d70`: 5 injections and 1 module
apply, the game builds, a world start runs the sidecar
(`vibe-runtime/1.0.0-beta.1 (Java 27)`, profile `forge-1.21.1-52`, lifecycle
complete), and `/vibe status`, `/vibe mods`, `/vibe reload` and `/vibe export`
answer in chat. See [docs/NATIVE_MOD.md](docs/NATIVE_MOD.md).

The limit is unchanged: Java runs in Vibe's own process beside Horizon, not in
Horizon's world.

## Horizon content (`.hmod`)

The release also ships working Horizon content bundles:

- `litematicatool.hmod` — built from `litematicatool-forge-2.0.0.jar` (MIT).
  It carries the mod's assets, its recipe, and an item declaration:
  `the_stick` copies the vanilla `minecraft:stick` template, with the mod's own
  model and texture. Verified in Horizon 0.2.97 on Minecraft 26.3:
  `horizon-ctl give litematicatool:the_stick` answers `{"given":1,"ok":true}`
  and the item appears in the inventory.
- `vibetest.hmod` — a minimal test bundle with one item (`vibetest:ruby`)
  and one block (`vibetest:ruby_block`).
- `SHA256SUMS.txt` — checksums for every asset.

```powershell
vibe horizon install litematicatool.hmod
# Installed ...\horizon-mods\litematicatool.hmod
#   horizon-mods.txt: mod.litematicatool:true (on)
```

Then start Horizon and run `/give litematicatool:the_stick`.

## Highlights

- Self-contained install: the release zip bundles the Java runtime **and an
  optimized JRE** (`java/runtime/`), and `vibe.exe` resolves both beside the
  executable, not from a build-machine path. No Java install is required.
- Fast startup by default: a jlink image with a CDS archive and
  `-XX:TieredStopAtLevel=1 -XX:+UseSerialGC -XX:-UsePerfData`, about 78 ms of
  JVM startup instead of 131 ms. `VIBE_JAVA_ARGS` overrides the flags.
- `vibe run mods` loads the Forge jars you drop in `mods/` directly. Vibe
  inspects each jar read-only and reports blocked mods with evidence.
- `vibe horizon export --item-template NAME=TEMPLATE` declares an item a Forge
  mod registered in Java: it writes `data/<id>/horizon/item/NAME.json` copying
  a vanilla template, and the 26.3 `assets/<id>/items/NAME.json` definition
  when the jar ships the old `assets/<id>/models/item/NAME.json`.
- `vibe horizon connect` verifies a live Horizon instance end to end:
  `horizon-ctl` discovery, control socket, player in world, pending chunks,
  Minecraft version, and the Horizon content API version.
- `vibe horizon install` writes `mod.<id>:true` to `horizon-mods.txt` (Horizon
  leaves a content mod off until that line exists) and defaults `--game-dir` to
  the Horizon game home (`HORIZON_HOME`, then `%APPDATA%\horizon`).
- 23 `vibe-horizon` unit tests cover discovery, connection checks, export,
  validation, installation, enabling, and item declarations.

## The hard limit, stated plainly

Horizon is a Rust engine with no JVM. A Horizon `.hmod` is data and assets only:
it cannot execute Java. Vibe therefore runs Forge jars in its own JVM sidecar,
and for Horizon it exports what Horizon can actually load (blocks, items,
recipes, models, textures). Java entrypoints, Mixins, access transformers, and
coremods are reported, never executed.

An item or block a mod registers only in Java has no Horizon declaration unless
you state one with `--item-template`; there is no automatic detection.

## Verified against Horizon 0.2.97

- `vibe horizon connect` reports `ready: yes` against a running Minecraft 26.3
  game in the `VibeTest` world.
- Horizon loads the Vibe-exported bundles:
  `Horizon: content from 2 mod(s) in ...\.horizon-cache\mod-content`.
- Registered content: 1 block and 3 items; the game went from 35,723 to 35,724
  block states and from 1,658 to 1,661 items.
- `horizon-ctl give litematicatool:the_stick` → `{"given":1,"ok":true}`, and
  the item is in the inventory.
- From the released zip, in a clean folder with no Java on `PATH`: `vibe doctor`
  reports the bundled runtime `[bundled, optimized]`, and `vibe run mods` loads
  a jar dropped into `mods/`.

## Requirements

- Nothing beyond Windows 10/11: the zip bundles an optimized Java 27 JRE.
- To build from source: JDK 17 or newer, plus `jlink`/`jmods` for the bundled
  runtime.
- Optional: a Horizon installation with `horizon-ctl` for `vibe horizon probe`
  and `vibe horizon connect`.
